Research

Project Trinity

Project Trinity is the AI party: the tank, healer and DPS that run with you, made to be extremely competent, like a raid team chasing leaderboards and day-one clears.

I

How the party plays

The arena publishes what's happening around the party: where the boss is facing, what it's winding up, who's hurt, what's on the floor. Each hero's brain reads those facts and picks one thing to do, then sends it to the game like a player's button press would.

Project Trinity's AI sees what you'd see and nothing more. It has no secret view of a fight. The only thing held back is knowledge, and only where that serves the raid leader fantasy: it's told less, never made worse.

You lead it. The Trinity Dial sets how safe or how greedy the party plays, and your orders (focus a target, focus the adds, help a teammate) outrank it.

II

How the research is done

It's half research, half game development: a machine learning project and a game built at once.

The fights run without a picture, in the cloud, over and over, each run from a different seed. Every choice each hero makes is written down with the reason it won, so a wipe can be read back step by step.

A change to how the party plays counts only when it holds up across many runs, not one lucky pull. Then each change is played and watched before it goes in.

The party doesn't rewrite itself. Its choices come from rules and tuning in the game's code, and after the runs those are changed by hand where it fell short; a change stays only if it holds up.

III

How the game is built

The way the game is built is part of the research too. It started small and kept growing into what it is now: one orchestrator and a seat for each job, each working off a sheet with a line to knock off.

Every change is checked, reviewed and watched in the game before it goes in.

Deeper pieces on each of these will come as devlog posts.
